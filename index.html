Section 01 · Epistemology, State Topology & Tool State Machine

两大提示词体系的哲学与工程逻辑对比（8 大核心维度）

左边是 Argon 在原版提示词下反复出现的真实翻车病症与底层成因，中间是 Google Antigravity 原版提示词的逻辑缺陷，右边是我们结合 Sourcegraph Amp (deep.md.njk / oracle.ts / ju 体检表) 与 Google Cloud《Argon 开发者指南》设计的替换逻辑。

✕ Antigravity 原版设计哲学（平台耦合与仪式感驱动 · 50.7 KB）
把大模型当成「需要写周报、查归档、顺带推销 IDE 功能的文员」
  • • 重仪式、轻实证：花了 11,000+ 字节规定怎么往 brain/<id>/ 写 Markdown 报告、怎么画轮播图和 `.url.json` 书签，却对“写代码前必须先读源码”只字未提；
  • • 强制历史二手摘要前置：开局强迫模型先查本地 KI 知识库摘要（哪怕早已过时），而不是直接用 `grep_search` 看当前分支的真实代码；
  • • 放任底座缺陷：完全忽略了 Gemini 4 Argon 底座预训练中“低置信度时强行估算（estimate if unsure）”与“工具调用前夹杂散文易崩溃”的模型脾气。
✓ Amp × Argon 重构版设计哲学（实证闭环与最小自由度 · 4.6 KB）
把大模型当成「直奔源码、外科手术式修改、用测试说话的资深搭档」
  • • 显式挂起底座估算本能：第一条即点名宣布预训练的“估算规则”对代码库事实挂起（SUSPENDED），没在本会话 read_file 读过的文件一律禁止断言；
  • • 零绕路直接交付：砍掉全部 `brain/` 外置报告与 KI 前置教条，所有结论、方案、Diff 直接在对话框交付，杜绝 ArtifactMetadata 路径报错；
  • • 顺应 Argon 状态机脾气：严格执行 Clean Tool Turns（零散文前戏、禁冒号）、edit_file 3~5 行唯一锚点护栏、以及按爆炸半径匹配的验证闭环。
